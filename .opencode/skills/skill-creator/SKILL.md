# Skill: skill-creator

**Назначение:** Создание новых скиллов (SKILL.md) и агентов (.md) по стандартным шаблонам с полным соблюдением конвенций проекта
**Триггеры:** `skill`, `скилл`, `agent`, `агент`, `create skill`, `новый скилл`, `новый агент`, `skill-creator` (только явный вызов по запросу пользователя)
**Инструменты:** `glob`, `read`, `write`, `edit`, `question`, `skill`, `bash`

## 1. Определение типа сущности

### 1.1 Вопрос пользователю

При получении запроса "создай скилл" или "создай агент", спросите:

```
Какую сущность нужно создать?

1. **Skill** — скилл для расширения инструкций агента:
   - Расположение: \`.opencode/skills/<name>/SKILL.md\`
   - Есть frontmatter, триггеры, flowchart, нумерованные секции
   - Используется через \`skill\` tool

2. **Agent** — описание роли для subagent:
   - Расположение: \`.opencode/agents/<name>.md\`
   - Без frontmatter, H2 секции без нумерации
   - Используется через \`task\` tool с \`subagent_type\`
```

### 1.2 Ключевые различия

| Характеристика | Skill | Agent |
|---|---|---|
| **Frontmatter** | ✅ Обязательно (\`name\`, \`description\`) | ❌ Отсутствует |
| **Нумерация секций** | ✅ H2: \`## 1.\`, \`## 2.\` | ❌ H2 без номеров |
| **Flowchart** | ✅ Опционально (ASCII) | ❌ Обычно нет |
| **Директория** | Поддиректория в \`skills/\` | Прямо в \`agents/\` |
| **Имя файла** | Всегда \`SKILL.md\` | \`<name>.md\` (уникальное) |
| **Триггеры** | В metadata block | Нет триггеров |
| **Примеры** | \`migration-wizard\`, \`security-audit\` | \`senior-backend-django-ninja\`, \`git-commit\` |

## 2. Шаблон: Skill (SKILL.md)

### 2.1 Структура директории

```
.opencode/
└── skills/
    └── <skill-name>/          ← kebab-case
        └── SKILL.md           ← всегда это имя
```

### 2.2 Обязательные элементы

| # | Элемент | Где | Пример |
|---|---|---|---|
| 1 | **Frontmatter: \`name\`** | YAML блок | \`name: migration-wizard\` |
| 2 | **Frontmatter: \`description\`** | YAML блок | *Safe creation...* |
| 3 | **H1 Heading** | После frontmatter | \`# Skill: migration-wizard\` |
| 4 | **\`**Назначение:**\`** | Metadata block | *Безопасное создание миграций* |
| 5 | **\`**Триггеры:**\`** | Metadata block | \`migration\`, \`миграция\`, \`migrate\` |
| 6 | **\`**Инструменты:**\`** | Metadata block | \`Django migrate\`, \`sqlmigrate\` |
| 7 | **Separator \`---\`** | После metadata | \`---\` |
| 8 | **Нумерованные H2 секции** | Тело | \`## 1. Безопасные Schema миграции\` |
| 9 | **Separator \`---\` между секциями** | Между H2 | \`---\` |

### 2.3 Пример frontmatter

```yaml
---
name: test-generator
description: Automated creation of pytest tests for Django Ninja API endpoints following project patterns and coverage requirements
---
```

### 2.4 Пример metadata block

```markdown
**Назначение:** Автоматическое создание pytest-тестов для API endpoints, сервисов и моделей
**Триггеры:** \`test\`, \`тест\`, \`pytest\`, \`написать тест\`, \`покрытие\`, \`coverage\`
**Инструменты:** \`pytest\`, \`pytest-django\`, \`TestClient\`, \`factory boy\`, \`glob\`, \`read\`
```

## 3. Шаблон: Agent (.md)

### 3.1 Структура директории

```
.opencode/
└── agents/
    ├── <agent-name-1>.md      ← kebab-case.md
    ├── <agent-name-2>.md
    └── ...
```

### 3.2 Общие H2 секции (по частоте из 7 агентов)

| Секция | Частота | Назначение |
|---|---|---|
| \`## Role\` / \`## Profile\` | 6/7 | Краткое описание роли |
| \`## Primary Objective\` | 5/7 | Главная цель агента |
| \`## Stack Awareness\` / \`## Expertise\` | 6/7 | Технологический стек |
| \`## Core Principles\` / \`## Working Principles\` | 6/7 | Принципы работы |
| \`## Preferred Workflow\` / \`## Workflow\` | 5/7 | Шаги выполнения |
| \`## Output Requirements\` | 5/7 | Формат результата |
| \`## Quality Bar\` | 5/7 | Критерий готовности |

### 3.3 Шаблон для технического агента

```markdown
# <Full Role Name> Agent

## Role
<краткое описание роли на русском>

## Primary Objective
<главная цель, что должен дойти агент>

## Stack Awareness
- <технология 1>
- <технология 2>
- ...

## Repository Context
- <директория 1>
- <директория 2>
- <ключевые файлы>

## Core Principles

### 1. <Название принципа>
<описание>

### 2. <Название принципа>
<описание>

## Preferred Workflow
1. <шаг 1>
2. <шаг 2>
3. <шаг 3>
...

## Output Requirements
1. **<Название>** - <описание>
2. **<Название>** - <описание>
...

## Quality Bar
- <критерий 1>
- <критерий 2>
...
```

## 4. Сбор требований через adaptive questions

### 4.1 Для Skill

Задавайте вопросы последовательно:

```
Вопрос 1: Какое назначение у этого скилла?

Вопрос 2: Какие триггеры должны вызывать этот скилл?
(Ключевые слова на русском и английском)

Вопрос 3: Какие инструменты или технологии используются?

Вопрос 4: Какие основные секции должны быть?
```

### 4.2 Для Agent

```
Вопрос 1: Как называется этот агент и какая у него роль?

Вопрос 2: Какой стек технологий использует этот агент?

Вопрос 3: Какие ключевые принципы должен соблюдать агент?

Вопрос 4: Какой формат вывода ожидается?
```

### 4.3 Критерий "достаточно информации"

Останавливайте когда:
1. Понятно **что** должен делать скилл/агент
2. Понятна **структура** (основные секции)
3. Пользователь сказал "достаточно"

## 5. Языковые конвенции

### 5.1 Таблица языков

| Элемент | Skill | Agent | Язык |
|---|---|---|---|
| \`name\` в frontmatter | ✅ | ❌ | **Английский** (kebab-case) |
| \`description\` в frontmatter | ✅ | ❌ | **Английский** |
| H1 Heading | ✅ | ✅ | **Английский** |
| \`**Назначение:**\` | ✅ | ❌ | **Русский** |
| \`**Триггеры:**\` | ✅ | ❌ | **Смешанный** (RU+EN) |
| H2/H3 заголовки | ✅ | ✅ | **Английский** |
| Текст описания | ✅ | ✅ | **Русский** |
| Комментарии в коде | ✅ | ✅ | **Русский** |
| Код | ✅ | ✅ | **Английский** |

### 5.2 Маркеры в коде

| Маркер | Значение |
|---|---|
| \`# ❌ Опасно\` | Критическая проблема, уязвимость |
| \`# ❌ Неправильно\` | Логическая ошибка, bad practice |
| \`# ✅ Безопасно\` | Правильное security-решение |
| \`# ✅ Правильно\` | Правильное общее решение |

## 7. Валидация и чеклист

### 7.1 Checklist для Skill

- [ ] \`name\` существует и в \`kebab-case\`
- [ ] \`name\` совпадает с именем директории
- [ ] \`description\` на английском
- [ ] H1: \`# Skill: <name>\`
- [ ] \`**Назначение:**\` на русском
- [ ] \`**Триггеры:**\` содержит русские + английские слова
- [ ] Минимум одна нумерованная H2 секция (\`## 1.\`)
- [ ] Разделители \`---\` между секциями
- [ ] Директория: \`.opencode/skills/<name>/\`
- [ ] Файл: \`.opencode/skills/<name>/SKILL.md\`

### 7.2 Checklist для Agent

- [ ] H1 существует и заканчивается на \`Agent\`
- [ ] Есть \`## Role\` или \`## Profile\`
- [ ] Нет нумерации у H2 секций
- [ ] Файл в \`.opencode/agents/\` (не поддиректория)
- [ ] Имя файла: \`<kebab-case>.md\`
