# План: Создание мета-скилла "skill-creator"

## Task Overview
Создать скилл, который стандартизирует и автоматизирует процесс создания:
1. **Новых скиллов** (`.opencode/skills/<name>/SKILL.md`)
2. **Новых агентов** (`.opencode/agents/<name>.md`)

Следуя всем существующим конвенциям проекта.

## Context Analysis

### Формат 1: Skills (.opencode/skills/<name>/SKILL.md)

**Структура технических скиллов:**
```
Frontmatter → H1 → Metadata → --- → Flowchart → --- → Нумерованные секции → --- → Checklist
```

**Обязательные элементы:**
1. **YAML Frontmatter** (`name`, `description`)
   - `name`: kebab-case, совпадает с директорией
   - `description`: английский, одно предложение

2. **H1 Heading**: `# Skill: <name>`

3. **Metadata Block**:
   ```
   **Назначение:** <русский текст>
   **Триггеры:** <keyword1>, <keyword2>, ...
   **Инструменты:** <tool1>, <tool2>, ...
   ```

4. **Нумерованные секции** (`## 1.`, `## 2.`, ...)
   - Внутри: код с `# ❌ Опасно` / `# ✅ Безопасно`

5. **Разделители `---`** между всеми крупными секциями

**Опционально:**
- ASCII Flowchart
- Финальный Checklist

**Директория:** `.opencode/skills/<kebab-case-name>/SKILL.md`

---

### Формат 2: Agents (.opencode/agents/<name>.md)

**Структура:**
```
H1 → H2 секции (без нумерации)
```

**Обязательные H2 секции (паттерн из 7 агентов):**

| Секция | Частота | Назначение |
|--------|---------|------------|
| `## Role` / `## Profile` | 6/7 | Краткое описание роли |
| `## Primary Objective` | 5/7 | Главная цель |
| `## Stack Awareness` / `## Expertise` | 6/7 | Технологии |
| `## Core Principles` / `## Working Principles` | 6/7 | Принципы работы |
| `## Workflow` / `## Preferred Workflow` | 5/7 | Шаги выполнения |
| `## Output Requirements` | 5/7 | Формат результата |
| `## Quality Bar` | 5/7 | Критерий готовности |

**Опциональные секции (по типу):**
- `## Repository Context` / `## Scope` - что обслуживает
- `## Guidelines` / `## Logic` - правила
- `## What To Check` / `## What To Analyze` - что проверять
- `## Checklist` - чеклисты
- `## Anti-Patterns` - что избегать

**Именование файла:** `<kebab-case-name>.md`

**Расположение:** `.opencode/agents/<name>.md` (прямо в директории, не поддиректория)

**Отличия от Skills:**
- ❌ Нет YAML frontmatter
- ❌ Нет нумерованных секций
- ❌ Нет flowchart
- ❌ Файл не в поддиректории

### Языковые конвенции (общие для обоих)

| Элемент | Язык | Пример |
|---------|------|--------|
| `name` (frontmatter) | Английский | `security-audit` |
| `description` (frontmatter) | Английский | *Safe creation...* |
| H1 Heading | Английский | `# Skill: security-audit` |
| `**Назначение:**` | Русский | *Поиск и устранение уязвимостей* |
| `**Триггеры:**` | Смешанный | `security`, `уязвимость`, `audit` |
| H2 секции | Английский | `## 1. Dependency Scanning` |
| Комментарии в коде | Русский | `# Установка`, `# ❌ Опасно` |
| Код | Английский | `pip install pip-audit` |
| Checklist | Смешанный | `SECRET_KEY не default` |

## Detailed Plan

### Скилл "skill-creator" будет содержать:

#### 1. Frontmatter
```yaml
---
name: skill-creator
description: Standardized creation of SKILL.md and Agent .md files following project conventions for structure, naming, and bilingual content
---
```

#### 2. Metadata Block
- **Назначение:** Создание новых скиллов (SKILL.md) и агентов (.md) по стандартным шаблонам
- **Триггеры:** `skill`, `скилл`, `agent`, `агент`, `create skill`, `новый скилл`, `skill-creator` (только явный вызов)
- **Инструменты:** `glob`, `read`, `write`, `edit`, `question`, `skill`

#### 3. Workflow Flowchart
```
Запрос: создать скилл или агент
        │
        ▼
┌──────────────────────────┐
│ 1. Определить тип        │
│    - Skill?              │
│    - Agent?              │
└───────────┬──────────────┘
            │
            ▼
┌──────────────────────────┐
│ 2. Сбор требований       │
│    - Назначение          │
│    - Ключевые секции     │
│    - Триггеры (для skill)│
└───────────┬──────────────┘
            │
            ▼
┌──────────────────────────┐
│ 3. Анализ похожих        │
│    скиллов/агентов       │
└───────────┬──────────────┘
            │
            ▼
┌──────────────────────────┐
│ 4. Создание по шаблону   │
│    Skill: поддиректория  │
│    Agent: файл в agents/ │
└───────────┬──────────────┘
            │
            ▼
┌──────────────────────────┐
│ 5. Наполнение секциями   │
└───────────┬──────────────┘
            │
            ▼
┌──────────────────────────┐
│ 6. Валидация конвенций   │
│    - структура            │
│    - языковая политика   │
│    - именование          │
└──────────────────────────┘
```

#### 4. Нумерованные секции

**Секция 1: Определение типа сущности**
- Вопрос: Skill или Agent?
- Различия между форматами

**Секция 2: Шаблон Skill (SKILL.md)**
- Полный шаблон со всеми полями
- Пример заполнения
- Структура директории

**Секция 3: Шаблон Agent (.md)**
- Полный шаблон H2 секций
- Рекомендуемые секции по типу агента
- Примеры существующих агентов

**Секция 4: Сбор требований через adaptive questions**
- Ключевые вопросы для Skill
- Ключевые вопросы для Agent
- Критерий "достаточно информации"

**Секция 5: Языковые конвенции**
- Таблица: какой элемент на каком языке
- Правило смешанного содержимого
- Примеры правильного/неправильного

**Секция 6: Паттерн "Проблема-Решение" в коде**
- Как использовать `# ❌ Опасно` / `# ✅ Безопасно`
- Примеры

**Секция 7: Создание файлов и директорий**
- Для Skill: `.opencode/skills/<name>/SKILL.md`
- Для Agent: `.opencode/agents/<name>.md`
- Именование: kebab-case

**Секция 8: Валидационный чеклист**
- Проверка frontmatter (для skill)
- Проверка структуры H1/H2/H3
- Проверка языковых конвенций
- Проверка именования файлов
